## 判斷與除錯

- **量不到效果時先確認「量測環境有沒有讓那件事發生」，再去懷疑設定**：兩個不同的設定給出一模一樣的錯誤結果，變因就不在設定上（Monaco 在 `show:false` 的視窗不做高亮；rAF 在視窗被遮住時不觸發）。
- **先量再改**：直覺說要改的那個開關，量過之後常常不該改。
- **「三個結果都一樣壞」不等於變因已控制**（Q4／Q8／f16 缺陷數相近，其實三次跑的是同一條錯路徑）；對照實驗的樣本也不能從其中一組的失敗集挑。
- **沒滿足前提的觀察不能推翻假設**（token 還有 7 分鐘壽命時跑 CLI，expiry 當然不動）。
- **同一種故障上游可能給你兩種說法**（`Budget 0 is invalid` 與看起來像整包壞掉的 `invalid argument`）。
- **「查不到」先確認是查不到還是自己送錯**：外部查詢失敗先用 `curl` 原樣打一次再下結論。
- **工具回「成功」而結果明顯不對時先驗產物、不要重跑**；建置產物出怪事整個刪掉重打，不要原地重試也不要先懷疑自己剛寫的程式碼。
- **「驗證用」的指令也會改壞現場**：`@electron/asar extract-file` 是**寫檔**不是印出來，在專案根目錄跑會蓋掉自己的 `package.json` 且毫無輸出。會寫檔的工具一律 `cd` 到暫存目錄再跑；蓋掉了用 `git checkout-index -f --` 救回未提交的那版。
- **Windows 上「找不到誰鎖住檔案」多半是找的方法不對**：`Get-CimInstance Win32_Process` 只看得到命令列，要用 `handle64` 或 Restart Manager 的 P/Invoke（免提權）。被鎖住也不代表沒路走——先問「它擋的是哪一種操作」（那個 handle 擋 delete 不擋 write）。
- **「這件事做不到」的結論留在註解裡久了會變成事實**（右 Alt「攔不下來」，直到專案長出 .NET sidecar）。
- **「載得起來」本身要有測試**：`module.exports` 列一個沒定義的名字是**載入期** ReferenceError，`node --check` 與單元測試全綠。
- **一個功能「畫得出來」不等於「算得出來」**（Monaco 沒有 Worker 時 diff 兩欄照畫、一條變更都不標）：畫面＋計算兩段都要各有斷言。
- **引進大型第三方前端套件前先確認它的 build 形式跟本專案的載入方式相容**（Monaco 的 ESM 有 98 個 `import './x.css'`），這一步要排在寫任何整合程式碼之前；同時看它拖了什麼進來（`pdfjs-dist` 帶一個 37MB 的 `@napi-rs/canvas`）。
- **「這個平台有沒有內建 X」一定要實測**（Electron 43 沒有 PDF 檢視器，`plugins: true` 也長不出來）。
- **移植別人的架構要先找出「核心只有幾個資料結構」**；借的是**互動模型**不是實作量級（判準：使用者每天碰幾次 vs asar 大多少、多幾條失效路徑）。移植純函式時連**哨兵值**一起檢查（`-1` 是算得出來的合法分數，要改回 `null`）。
- **新寫的初始化函式一定要確認真的被呼叫**（三顆側欄模式鈕整組無效，只因為 init 沒接上）。
- **解析帶語意的 ID 前先驗版本**（UUIDv7 的時間戳，混進 v4 會算出未來幾千年）；子代理／fork 的重播防護不可只依賴單一標記。
- **控制字元不要直接寫進原始碼**：`node --check` 照樣過，但 git／grep 從此把整個檔案當二進位。多層轉譯（heredoc → 樣板字串）也會吃掉跳脫序列，寧可用 `String.fromCharCode`。含反斜線的程式碼不要用 heredoc 寫。
- **同一個寫法失敗兩次就換方法**（字串替換連兩次錨點對不上，就改用會報錯的工具）。
- **在 CLI/Agent 環境啟動 GUI 程式不要在子 shell 掛著等或重定向輸出**（Job Object 會把子程序整組砍死；PowerShell 也不會等 GUI 子程序，管線提早關閉會 EPIPE）：改用 `Invoke-CimMethod Win32_Process Create`。
- **「單位到底是多少」要找對面自己附的文件，不要拿實收金額反推**（Grok 的 ticks）。
- **儀表的「目前」跟「上限」是兩件事**（PPT Limit 是牆、Package 才是正在吃的瓦數）；負載 0 是真的閒置，不可寫成 null。
- **相容舊 App 的庫要拷走再寫**（跟還在跑的程式搶同一顆 SQLite 會把兩邊都寫壞）；外掛把埠寫死時只能重試，換埠等於外掛整組失效。
- **額度／端點要先對真實回應再命名視窗**（Ollama 現行是 `limits.monthly`、Command Code 的月額度是剩餘值）。

## 外部整合

- **移植時，來源的「奇怪選擇」通常是它踩過的坑**（AGY 的端點順序 sandbox → daily → prod 是實測結論不是偏好）。
- **「照抄那個專案」之前先問「他們那樣做對嗎」**（cc-switch 對 Codex 用 device code，他們自己文件寫明那是逆向的）；照抄上游的資料模型會毀掉使用者的設定（整檔換 `settings.json`）。
- **使用者指定的接法也要先驗過**：實測兩分鐘 > 照抄一句需求（Command Code 原生講 Anthropic，照做會多接一層轉換）。
- **同一家供應商的格式不能只看一個預設**：「上游格式」與「驗證格式」要分開存。
- **mock 測得再綠也證明不了對面長什麼樣**：我理解錯的地方 mock 會忠實跟著錯。
- **先問對面長什麼樣，再決定要不要自己寫**：`probe-hf-router.js` 一跑，原本要寫的三個功能變成零程式碼。**架構押在哪個假設上，那個假設就要最先驗**。
- **官方的自動化只在「你沒設」的時候生效**（`-fit on` 只調整使用者沒設的參數，主動寫死 `gpu-layers` 等於把它關掉還換成更差的估算）。
- **翻譯／相容層不該覆蓋使用者的明確指名**（上游真的有 `gemini-3-flash`）。
- **代理不該把上游的狀態碼原樣丟回去**：只有對客戶端有行動意義的才透傳。
- **更新方式要看它「實際上是怎麼裝的」**：「有 npm 套件」不等於使用者是用 npm 裝的。
- **「清掉快取」不等於「換一個 token」**；反過來，語意窄的旗標只能由產生該語意的路徑設定（`mustRefresh` 被一般失敗清理順手設起來＝憑證永久卡住）。
- **「該續期了」不等於「已經不能用了」**：refresh deadline 與 expiry deadline 是兩條線。
- **代跑外部 CLI 的 stdio 很要命**：`execFile` 留一條永不 EOF 的 stdin，對方會卡到逾時。

## 資料、計價與統計

- **統計類功能先確認「涵蓋率」再談「準確率」**：價目表再準，對不到 key 就是零。
- **「累計」與「單輪」長得一模一樣，加錯差十倍**（`total_token_usage` vs `last_token_usage`）。
- **真實資料才問得出正規化夠不夠**：自己寫的 fixture 全過，一跑真實記錄就冒出一堆對不到的 id。
- **「填 0」比「留空」更會騙人**：沒有單價就回 `null` ＋ 在 UI 明講少算了幾次請求。
- **同一個欄位有兩種價錢時不能只算便宜的那種**（cache creation 有 78% 是 1 小時檔）。
- **上限值是會靜靜吃掉資料的東西**（單行／單檔上限「超過就跳過」且不留痕跡）。
- **同一件事被兩層各做一次，上層會把下層的資訊吃掉**：補值函式若依賴呼叫端才有的上下文，就只能有一個呼叫端；修掉「先補一輪」之後，失敗路徑仍會走同一個補值函式。
- **來源未連線時不可合成保守額度**（先判 account status 再 merge，否則會生出被相信的假數字）。
- **「管線全綠」不等於「金額是對的」**：自帶金額的來源（Grok ticks）整條沒人驗過，使用者拿計算機一敲就抓出 10 倍。倍率整齊（剛好 10.00）就是單位／口徑錯的指紋。
- **游標認絕對路徑會在檔案搬移時整份重複計算**（模擬 `renameSync` 就能重現，不必等真的搬移）。
- **只給一個總數的統計等於沒說**：實測 97.5% 的 token 是 cache read；**數字讓人驚訝時先問「它由什麼組成」**。
- **「大部分時候對」的公式最難抓**：規格裡明寫的欄位一律優先讀，推導只當退路，**而退路不可以回 0**。

## 測試

- **CDP 點按鈕會被吞掉**：模組還沒掛上監聽時點下去等於沒點，而且畫面永遠不會再重畫——等待條件要包住點擊本身（「點到看得到結果為止」），不是先點一次再等。
- **測試測的是被繞過的那一層，就會一直是綠的**（斷言直接餵下游函式，production 在上游就做壞了）。
- **新寫的回歸測試一定要先在修復前跑一次**，紅了才算數，不然只是把當下的行為寫成斷言。
- **測試突然變紅時先確認是「程式壞了」還是「測試終於誠實了」**（補上暫存 user-data-dir 之後假綠燈才現形）。
- **只驗「功能開啟時」的斷言等於半套**：每加一條 UI 斷言就反問「關著／空的／還沒載入時我量過嗎」。
- **「執行中」不等於「壓到了」**、**「偵測得到 GPU」不等於「正在用 GPU」**：要用第三方工具量一個能分辨的數字。
- **同一份程式碼算出來的數字不能用它自己的測試證明算得對**；重複計算的證明要拿另一份檔案核銷。
- **E2E 跑在使用者的真實資料上**：定位條件必須是「我自己建的那個」（`[data-id]`），不可用「第一列」或總數。
- **會外溢到 App 之外的動作，測試路徑一定要先切斷**（模擬 Ctrl+V、taskkill、改使用者設定檔）。
- **UI 斷言要等「量得到尺寸」而不是睡固定時間**；忙碌的機器上固定 sleep 會變成假紅燈。
- **斷言不要綁「長度」或「位置」這種會隨設計調整的量**（文案收到 7 字就變假紅燈）。
- **多開一扇視窗＝多一個 CDP page target**；同一時間只能跑一支 CDP 測試（單一實例鎖）。
- **批次 sed 換識別字會把斷言改成永遠成立**（`=== false` 變恆假、陣列塌成重複項）：改完 `git diff` 逐條看。
- **定位相關的斷言要量相對關係**（trigger 與 menu 的 left 差），只驗結構與旗標抓不到位移。
- **只驗截圖驗不到「原生控制項展開後」的樣子**（`<select>` 有一半由 OS 畫）。
- **「排查用的工具正常、正式路徑不正常」＝工具改變了現場**：先問工具多做了什麼（probe 的心跳剛好打開了被擋住的寫入縫隙）。回歸也要照這個修——只驗第一框會恆綠，要驗**連續好幾框**。
- **提權留下的殭屍程序會讓後續每一輪測試都紅**：每輪開始前先確認上一輪真的死透了（提權 sidecar 要 `Invoke-CimMethod Terminate`）。
- **要餵假資料給 renderer 不要鑽 contextBridge 的洞**（暴露的物件是 frozen＋non-configurable）：另外起一個 `contextIsolation: false` 的殼、換一個 preload 就好，並用 `showInactive()` 不搶焦點。
- **e2e 直接打 preload 方法時參數會先被 preload 轉換**（`webUtils.getPathForFile`）：要驗全鏈路就用真的 `Input.dispatchDragEvent`。
- **改動全域狀態的測試段落要收尾還原**（拖放成功會切走選中專案，後面依賴檔案樹的段落會撞空樹）。
- **pointer 拖曳的 e2e 終點要放鄰居的正中心**（落點是 closestCenter，放右緣會一次跳兩格）；CDP eval 拿回的 rect 是 JSON 字串，忘了 parse 會得到誤導人的型別錯誤。
- **e2e 別把小模型的用詞正確性當紅燈**（0.8B 會音譯專名、偶發幻覺）。

## UI 與樣式

- **修 A 的時候順手壓過瀏覽器內建樣式，會生出比 A 更大的 B**（`[hidden]`、`dialog:not([open])` 都被作者規則壓過）。
- **CSS 變數打錯不會報錯，它只是安靜地變成「沒有」**（或在 SVG `fill` 上變純黑）：寫新樣式前先 grep `themes.css`，回歸要量 `getComputedStyle` 的實際顏色。
- **`backdrop-filter` 會偷走 `position: fixed` 的定位基準**（跟 `transform`／`filter` 一樣）。
- **批次改 CSS 前先確認選擇器不是某條多選擇器規則的結尾**（曾把共用規則的 `background` 一起刪掉）。
- **包一層之後原本的 CSS 收斂就失效了**（`custom-select` 讓 `.select` 打在不佔位的元素上）：換 DOM 結構時要回頭搜「有誰用舊結構的選擇器在排版」，斷言要量寬高關係。
- **共用容器的內距寫在子元素上時，新子元素一定會漏**。
- **「字體大小都差不多」的根因可能是權重反轉**（分區標題比它管轄的欄位更小更灰）。
- **狀態樣式要比 hover 更高特異度**；把 `label` 當可點擊元件時要用同等特異度覆蓋 `display`。
- **原生下拉只能把收合態做好**（展開清單畫在頁面之外）：保留原生 `<select>` 當資料與事件來源、視覺自己畫；`optgroup` 沒有 `options` 集合。
- **hover 才出現的操作等於沒有**；**把資訊藏在點擊後面等於沒做**（對照組是拿來數「同一個資訊要幾次點擊」的）；**「按不下去的狀態顯示」不算功能**（列出一個使用者會想改變的狀態，就要在同一列給改變它的方法）。
- **值不准被截成「…」**：截掉的那筆等於沒有那筆資料，長字串要 `overflow-wrap: anywhere`。
- **圖表沒有 Y 軸等於把解讀丟給使用者**：柱狀圖的時間標籤要掛在繪圖區外；走勢圖兩條線各自縮放就要各標各的軸；讀不到值時 push 0 佔位會把自動縮放壓扁一整分鐘。
- **拖曳中改 DOM 順序就是卡頓與閃爍的來源**：只用 transform 送到記住的槽位、碰撞打靜態槽位，放開才動 DOM；可以拖的東西一律 `user-select: none`。
- **重畫整份清單會把「進行中的互動」洗掉**（待確認的刪除鈕、就地改名的輸入框都掛在 DOM 上）：改成就地更新那一列。
- **「整棵重畫」在小資料上看不出來，痛的是捲動位置**：展到第三層之後每點一次就跳回最上面——這種問題沒人會報 bug，只會讓人少用那個功能。
- **`await requestAnimationFrame` 在視窗被遮住時等於死結**：rAF 是「有就更好」不是流程的門檻。
- **可見狀態必須跟真正的資料上下文一起失效**（二次確認只記在 DOM、翻譯結果只在輸入變更時清）。
- **同一份資料要有單一來源**：檔案樹與 Git 狀態共讀 `gitStatus`；狀態比清單慢時要先清掉舊樹，否則使用者會點到上一輪的列。
- **浮層的外層也會吃滑鼠**（Monaco 的 `fixedOverflowWidgets` 把 tooltip 放到 host 外）：閃爍要用真實滑鼠事件＋`elementFromPoint`＋opacity 連續取樣找根因。

## Electron / Windows

- **啟動慢往往不是 Electron 本身**：量的是「點 exe 到視窗出現」，主因是頂層 require 整張模組圖。
- **外部程序也讀不到 asar 內檔案**（PowerShell、conhost）：這類功能一定要驗 final package。
- **不是每個 fs API 都懂 asar**：`copyFileSync` 讀得到、`fs.cpSync` 讀不到（不報錯，只留半套資料夾）。從源碼跑的測試永遠綠，只有打包版會壞——「要整包複製的東西」就先 `asarUnpack`。
- **外部執行檔一律指名絕對路徑**：Windows 的 CreateProcess 會找 System32，但 Node／libuv 的搜尋只看 PATH，所以 `whoami.exe`／`icacls.exe` 會抓到 Git Bash 的 MSYS 版；症狀是「換一個 shell 跑同一支測試就紅」。
- **打包「沒報錯」不等於打包成功**：別的程式抓著 `app.asar` 時產出的 asar 會每個檔案錯位、完全沒有錯誤訊息。Orca **連 `%TEMP%` 都監看**，要打到它看不到的碟。
- **打包產物「安靜壞掉」有兩種，症狀不一樣要分開認**（asar 錯位＝起得來但整頁 SyntaxError；EPERM 中斷＝啟動無 log）。
- **「檔案被別的程式抓著」之前先問「這個檔案為什麼這麼大」**（`EBUSY: unlink app.asar` 的真因是漏排了 `native/`，即時掃描抓住了 631MB 的 asar）。
- **透明視窗是坑**（白條殘留、`resizable` 失效、滑鼠事件異常）；覆蓋在別人程式上面的視窗第一個要問「它會不會偷走焦點」（`focusable: false` ＋ `showInactive()`）。
- **視窗還原座標要驗螢幕存在**；OS 層關閉（Alt+F4）要補發關閉事件。
- **啟動要有重入旗標**：按鈕 `disabled` 若在多個 await 之後才設，雙擊會起兩條管線。
- **切頁若只卸資源、不作廢工作，下一輪會把資源載回來**：清理清單是「作廢世代 ＋ 停工作 ＋ 卸資源」；prewarm 旗標不可早於 acquire 成功。
- **逐一列舉的 IPC 白名單，新增方法要同步補**：它讓「模組加方法」與「對外開放」變成兩件事，IPC 層／preload／單元測試全綠也擋不住。
- **同一個結構性陷阱出現在第二個模組時，要在那個模組的段落也補一條**：地雷筆記是「做這個模組時會讀到」才有用。
- **PowerShell 腳本要 BOM ＋ AutoFlush**；**`$env:*` 在被 spawn 的子程序裡不一定存在**（手動跑一切正常，看不出差別）。
- **OEM 沒填的欄位會回「看起來像資料的字串」**（`Default string`）：統一在一處清掉。
- **不確定安裝程式參數時先從 exe 裡撈 usage 字串**，不要用猜的一個個試；**「裝好了」跟「找得到」是兩件事**（DLL 在磁碟上但不在 PATH，症狀跟沒裝一模一樣）。
- **Windows 效能計數器選錯類別，慢十倍還不會有人告訴你**（`PerfFormattedData` vs `PerfRawData`）。
- **同一時間只能跑一支需要單一實例鎖的 App**；背景常駐時只有計時器被節流，訊息派送不會。
- **「預覽版已關閉」不一定真的關了**（`closeToTray`）：打包前用 `Get-Process | Where Path` 確認，只殺 `dist\win-unpacked` 那幾顆。

## 音訊 / ASR / 本地 LLM

- **靜音與非語言片段要在訊號層擋掉**，不要交給 AI 判斷（昂貴又易幻覺）。
- **括號式 meta-prompt 小模型會複誦**：指令放 system prompt、前文當上一輪對話。
- **失敗時別把原文冒充譯文寫進 history**（identity 前文＝few-shot 教模型複誦）；重試推論前要還原 chat history。
- **載入模型 ≠ 可快速推論**（首次 prompt 的 compute-graph 冷啟動 ~12.5s）。
- **別用 0.8B 當語言偵測器**（實測 ~43%，比漢字比例啟發式更糟）。
- **在地化詞彙表會竄改正確譯文**（OpenCC `twp` 把「參數」改成「引數」）；**自家「清理」也會製造污染**（無條件剝單側引號）。
- **不要用 regex 剝前綴當修復**：那是止血，代表 prompt 錯了。
- **切段策略要用實測收斂，別靠推理**（LinguaForge 的條列退化試了三版）。
- **佇列要有上限並丟最舊**；**await 後要重檢 session 狀態**（含 `finally` 裡）。
- **量化不背模型的鍋**：專名丟失、幻覺年份在 f16 全精度照樣發生。
- **使用者要的功能可能物理上不存在**：做一個「切了也沒差」的開關比不做更糟。
- **學習型功能要保守**：學錯了每句被改壞，而使用者不知道是誰幹的。
- **一組規則各自都對、合起來會錯**：字典每條各跑一次 `split/join` 會接力（`A→B` 之後 `B→C` 把 A 改成 C）。
- **沉默的截斷比拋錯難查十倍**（輸入上限與輸出 token 上限）。
- **「A 功能沒生效」通常不是 A 壞了，是 A 只活在管線的前半段**（字典有套也寫進 prompt，但模型回來之後沒再套一次）。
- **「保守」不是永遠的美德，要看單位長度**（一句指令不准重寫，一段口述就該重寫）。
- **提示詞裡的「輸出語言」會被模型當成翻譯指令**。

## 流程與溝通

- **錯誤訊息要寫給「還沒做到那件事」的人看**：先問「看到這句話的人手上有什麼、缺什麼」。
- **狀態碼分類不是「相近的收在一起比較整齊」，是「使用者下一步該做什麼」**（401 金鑰壞 vs 403 沒開通）。
- **UI 的求助訊息會把人帶去修錯的東西**（「有 1 個模型還沒設單價：unknown」其實是重複計算）。
- **錯誤必須浮上 UI**（狀態區＋連續失敗自動停止），只進 console 等於使用者看到永遠的「處理中…」。
- **使用者說「我這邊是對的」時先當真去驗證那個前提**：寫一支 probe 打真上游列出矩陣，比讀十遍程式碼快。
- **安全規範寫在文件裡不等於舊模組跟上了**：規則要按**性質**寫（「任何 ASR 來源」「上游可控又會顯示給使用者的字串」）。
- **判斷該不該共用，看的是「取捨是不是同一個」不是「值長得像不像」**；設定欄位重複＝同一組金鑰要填兩次，判準是「端點協議一不一樣」。
- **改一個「取值」函式的 fallback 之前，先查有沒有人拿它的回傳值當守衛**；**一個函式被當兩件事用時，收緊其中一件會弄壞另一件**——改布林函式的語意前先看所有呼叫點在問什麼問題。
- **改 require 目標不是等價替換**：新模組需要什麼初始化，要沿著呼叫鏈往上找誰負責供給。
- **回報未處理項目時每一項都要帶「是／不是 bug」與依據**；**明確要求的功能不能只留在未來清單**。
- **使用者仍在操作電腦時不得移動滑鼠或搶前景焦點**；要手動開一份來玩走 `npm run dev:sandbox`。
- **「全部改成暫存 user-data-dir」會連帶搬走模型與所有設定**：缺什麼要在測試裡自己種。
- **「缺很多資訊」要先量再補，不要憑感覺列清單**。
- **原始碼裡可以躺著看不見的 NUL byte**（用 `\0` 當 key 分隔符時要寫跳脫）。
